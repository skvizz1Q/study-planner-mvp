# Study Planner MVP

---

### ПРОБЛЕМА
Студенти часто втрачають дедлайни та знижують свою успішність через велику кількість розрізнених завдань у різних месенджерах та відсутність єдиної точки контролю.

### ПІТЧ
**Study Planner** — це лаконічний інструмент для фіксації навчальних завдань. Користувач може миттєво додати дедлайн, відмітити виконання та бачити свій прогрес в єдиному місці без зайвого інформаційного шуму.

---

### ЦІЛЬ ПЕРШОЇ ІТЕРАЦІЇ (MVP)
Створити мінімально життєздатний продукт, який фокусується на трьох базових функціях:
1. **Створення:** швидке додавання нового завдання.
2. **Візуалізація:** перегляд актуального списку справ.
3. **Контроль:** маркування завдання як виконаного.

**Ядро цінності:** > Користувач додає завдання → Бачить його в списку → Відмічає виконання → Система фіксує успіх.

---

### КОРИСТУВАЦЬКИЙ СЦЕНАРІЙ
* **Умови початку:** Користувач відкрив головний екран системи.
* **Крок 1:** Натискання кнопки `Додати завдання`.
* **Крок 2:** Введення назви предмета та дати дедлайну.
* **Крок 3:** Підтвердження дії (Save).
* **Крок 4:** Візуальна перевірка появи завдання у загальному списку.
* **Крок 5:** Натискання на відмітку (чек-бокс) біля завдання.
* **Очікуваний результат:** Статус завдання змінюється на "Виконано", дані синхронізуються.

---

### КАРТА СТЕЙКХОЛДЕРІВ
| Роль | Очікування від продукту |
| :--- | :--- |
| **Студент** | Швидкість роботи, простота інтерфейсу, наочність дедлайнів. |
| **Розробник** | Стабільність коду, легкість масштабування, відсутність помилок у логіці. |
| **Викладач** | Чітка логіка ініціації та відповідність архітектурним вимогам. |

---

### КРИТЕРІЇ ПРИЙМАННЯ (ACCEPTANCE CRITERIA)
* Час створення завдання не перевищує **20 секунд**.
* Адаптивний інтерфейс.
* Збереження стану даних після перезавантаження сторінки.
* Інтуїтивно зрозуміла навігація без додаткових інструкцій.
